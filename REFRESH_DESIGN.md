# Actives Refresh Pipeline — Design

Status: APPROVED 2026-07-28 with four amendments (splice guardrails,
latest-state-wins RECONCILE, heights_off_market.csv rename, generator-owned
LIFE). Implementation staged (a)–(e), commit per stage.

## Problem

Every actives refresh is hand work: diff the HAR export against DATA by eye,
hand-bake reconcile constants (OFFMKT_727 / RELIST_727), hand-write CSV rows,
hand-edit LIFE notes. And because no refresh records what changed, the ask tab
can only see the current snapshot — "how many sold in the last month" is
unanswerable.

## Shape of the fix

One script consumes a dated pair of HAR CSVs, diffs them against DATA under a
shared address normalizer, and emits three machine-generated artifacts: a
dated changelog (history for the ask tab), the off-market CSV rows, and the
reconcile data (replacing the hand-baked constants). New pins are staged for
review, never auto-appended. OUT_OF_ZONE is enforced at diff time.

## File layout

```
refresh/
  refresh.py            # pipeline CLI (diff + emit artifacts)
  norm.py               # address normalization, importable + unit-tested
  apply_staged.py       # post-review: append approved pins to DATA/SEED
changes/
  index.json            # ordered list of changelog files + summary counts
  changes_2026-07-27.json
  changes_2026-08-10.json
staging/
  proposed_2026-08-10.json   # geocoded new listings awaiting human review
heights_solds.csv       # regenerated by the pipeline (name kept — viewer fetches it)
index.html              # gains ONE machine-writable marker region (see below)
```

Everything under `changes/` and `heights_solds.csv` deploys with the tree, so
the ask tab and Solds viewer fetch them same-origin.

## Address normalization (norm.py)

Single normalizer used on both sides of the diff. Handles every variant hit
this session:

```
norm("833 W 25th Street")            == norm("833 W 25th St, Houston, TX 77008")
norm("1122 E 27TH ST Unit#B")        == norm("1122 e 27th st unit b")
norm("1016 E 27 th Street")          == norm("1016 E 27th St")     # HAR "27 th"
norm("741 W 21st Street Unit#A")     -> key "741|a|w 21st"
```

Steps: lowercase → cut at first comma (drops city/state/zip) → fold `"N th"`
→ `"Nth"` → extract leading number → extract unit (`unit#a`, `unit# a`,
`unit a`, or a lone `a`–`f` token after the number) → strip street-type word
(st/street/ave/avenue/blvd/ln/dr/ct/rd) → collapse whitespace.
Key = `number|unit|street-core`. `1/2` streets pass through (`e 7th 1/2`).

Explicitly NOT solved by normalization: `5339 A Larkin` vs `5339 Larkin`
(letter-prefixed unit before the street name). The normalizer maps the "A" to
the unit slot for this pattern too, so the pair keys differ only in unit —
same as Unit#A/B pairs.

## The diff

Inputs: `refresh.py --date YYYY-MM-DD single.csv split.csv`

1. **Parse** both HAR variants: address-led headerless, or headered with an
   `Address` column. A file with neither → hard error naming the file
   (stats-view guard from CLAUDE.md).
2. **OUT_OF_ZONE first.** The regex is parsed out of index.html at runtime
   (single source of truth — no second copy to drift). Export rows matching
   it are recorded under `excluded` in the changelog and take no further part.
   The Larkin/Cornish re-add class dies here.
3. **Classify** against current DATA actives (kind==="active") + current
   reconcile state:
   - **matched** — in export and in DATA as active
   - **dropped** — active in DATA, absent from export → goes off-market
   - **relisted** — in export and currently in the reconcile off-list → flips
     back automatically (requirement 3), recorded in the changelog
   - **new** — in export, not in DATA → staged, not appended
4. **Dedupe guard for new listings**: each new listing's key is also checked
   against permit/deed pins (the pmt_833 / 2924 Watson / 1120 E 26th class).
   A hit stages the listing with a `mergeCandidate` pointing at the existing
   id, so review decides merge-vs-new instead of creating a duplicate.

## Artifact 1 — changelog

`changes/changes_YYYY-MM-DD.json`:

```json
{
  "date": "2026-08-10",
  "sources": ["single_810.csv", "split_810.csv"],
  "counts": {"matched": 57, "dropped": 6, "new": 3, "relisted": 1, "excluded": 3},
  "dropped":  [{"id": "act_x", "a": "…", "ty": "split", "disposition": "unconfirmed"}],
  "relisted": [{"id": "act_y", "a": "…", "offSince": "2026-07-27"}],
  "new":      [{"id": "act_z", "a": "…", "staged": true, "mergeCandidate": null}],
  "excluded": [{"a": "5339 Larkin Street", "rule": "5339.*larkin"}],
  "dispositionUpdates": {"act_w": "sold"}
}
```

`dispositionUpdates` lets a later run (or a hand edit) record Spencer's
rulings against ids dropped in an earlier file without rewriting history —
the ask tab merges them newest-wins. `changes/index.json` is the ordered file
list with per-file counts, so the ask tab can answer count questions from the
index alone and only fetch detail files when ids are needed.

**Backfill**: generate `changes_2026-07-27.json` (the 26 drops + exclusions)
and `changes_2026-07-28.json` (dispositions, 2 relists, 833 termination) from
this session's known facts, so history starts with what we already know.

## Artifact 2 — off-market CSV (renamed, amendment 3)

The file becomes **`heights_off_market.csv`** (`git mv` from
heights_solds.csv in the same commit as the generator's first CSV output).
The viewer's fetch path, download filename, and button label ("Solds" →
"Off Market") change with it. The pipeline regenerates it from DATA + the
full changelog: one row per currently-off-market id, disposition from the
newest changelog ruling, `date_off_market` from its drop event. Relisted ids
drop out automatically. Hand-written rows end.

## Artifact 3 — reconcile data (replaces OFFMKT_727 / RELIST_727)

**Recommendation: generated JS block spliced between markers — not fetched
JSON.** Reasons:

- The transform must run synchronously at seed time and immediately after the
  remote merge. A fetched JSON leaves a window where a returning browser
  renders stale tags and can remoteSave() them to the shared store before the
  fetch lands — exactly the stale-tab failure we spent this session fixing.
- Offline/local file: URLs keep working.
- The splice is an anchored edit between unique markers — consistent with the
  hand-authored-file rule; the machine owns only this region:

```js
/* RECONCILE:BEGIN — machine-generated by refresh/refresh.py. Do not hand-edit. */
const RECONCILE={
  "off":    {"act_x":{"t":"split","d":"2026-08-10"}, …},
  "relist": {"act_y":{"t":"split","d":"2026-08-10"}, …}
};
/* RECONCILE:END */
```

One generic `applyReconcile(pts)` replaces `applyOffmkt727` at both existing
call sites. Same guarantees as today: strips only `active_*` / adds one
`off_market_*` (off-list), the reverse for the relist-list; per-id dated note
prefix `"Off market as of <d>. "` (skipped if the notes already contain any
dated off-market line); strips any dated off-market prefix on relist; never
touches `pending` or phase tags; idempotent; `off` and `relist` are disjoint
by construction (the generator asserts it).

**RECONCILE is one entry per id, latest-state-wins** (amendment 2, confirmed):
an id lives in exactly one of `off` / `relist` / `pending` with a single
`{t, d}` — no dated batches accumulate. The `pending` bucket (added 7/28)
holds under-contract ids: the transform strips `off_market_*` and ensures the
`pending` tag; they are excluded from heights_off_market.csv and from all
Off Market counts/filters until they resolve to sold or terminated. When state changes, the generator replaces the
entry (relist → later drop moves it back to `off` with the new date, old
entry gone). History lives only in the changelog.

**Splice guardrails** (amendment 1): before writing index.html the generator
(1) runs `git pull --ff-only` and aborts on divergence, (2) builds the fully
spliced file in memory and re-parses it — DATA block valid JSON, RECONCILE
markers present exactly once and balanced, `applyReconcile` referenced at
both call sites, SEED_POINTS/LIFE still parseable — and refuses to write on
any failure, (3) is human-invoked only, never cron. Recorded in CLAUDE.md
hard rules.

## Staged pins (requirement 5)

`staging/proposed_YYYY-MM-DD.json` holds Census-geocoded candidates:

```json
[{"id": "act_new-slug", "a": "…", "prod": "Split Lot", "v": "$…", "sd": "…",
  "lat": …, "lng": …, "geocode": "Exact|Non_Exact|FAILED",
  "mergeCandidate": "pmt_… or null",
  "data": { …full DATA record… }, "seed": { …SEED_POINTS entry… }}]
```

Geocode failures stage with `FAILED` and no coords — never guessed. After
human review, `apply_staged.py --approve id1 id2 …` appends the DATA records
(before the `];`) and SEED entries (before the `}}`), runs the same
verification battery we ran by hand (JSON re-parse, no coordinate collisions,
field order), and refuses ids whose address matches OUT_OF_ZONE — belt and
suspenders. Merge-candidate approvals print the proposed anchored edit for
hand application (merges stay reviewed, per this session's precedent).

## Ask tab (requirement 6)

Lazy-load on first change-over-time question:

```js
async function loadChanges(){
  if(window._CHG) return window._CHG;
  const idx = await (await fetch('changes/index.json')).json();
  const files = await Promise.all(idx.files.map(f=>fetch('changes/'+f).then(r=>r.json())));
  // flatten to events: {date, type: off|relist|new, id, ty, disposition}
  window._CHG = buildEvents(files);   // dispositionUpdates applied newest-wins
  return window._CHG;
}
```

Question forms this enables (windowed reduces over the event list):

- "how many sold in the last month" → off events, disposition sold, date ≥ now−30d
- "how many went off market since the last update" → off events in the last file
- "how many new listings this month" / "…relisted…"
- "net active inventory change since July 27" → matched deltas + new − dropped
- split vs single breakdowns via `ty` on every event
- "what dropped and is still unconfirmed" → off events with no newer ruling

Deed-transfer counts need deed events in the same stream; the deed refresh is
a separate pipeline today, so the changelog schema reserves
`type:"deed_added"` but this design does not build it. The ask tab answers
"deed transfers since the last update" only once that pipeline also writes
changelog entries.

## What stays manual (requirement 7)

- **Disposition ground truth** — Spencer. The pipeline writes `unconfirmed`;
  rulings arrive as `dispositionUpdates` (hand edit or a
  `refresh.py set-disposition act_x sold` helper). Nothing infers sold vs
  terminated vs under-contract from an export.
- **Staged-pin review** — geocode sanity, merge-vs-new decisions, and the
  approve step. The pipeline proposes; a human appends.
- **OUT_OF_ZONE membership** — Spencer's zone judgment; the pipeline only
  reads it.
- **Live-map edits** — `pending` tags and any hand retags stay human; the
  reconcile transform continues to preserve them.
- **Pair-merge policy** — master selection and per-twin display remain code,
  not refresh data.
- **LIFE is generator-owned for listing-lifecycle ids** (amendment 4):
  changelog dispositions drive `s` and `note` mechanically — Spencer's
  ruling is entered once as a `dispositionUpdates` entry and flows to LIFE,
  the CSV, and the badge with no hand edit of index.html. Mapping:
  drop+unconfirmed → `s:"sold"`, note "Off market as of <d> — was active MLS
  listing"; sold → note "Sold as of <d> …"; under contract → note "Under
  contract as of <d> …"; terminated → note "Listing terminated as of <d> …";
  relist → `s:"ready"`, note "Lifecycle: Ready for market — active MLS
  listing". Fields that REMAIN hand-maintained: `fin` (punch-list judgment),
  `ph` (construction phase on uc entries), `ty` (product), and every `deed` /
  `uc` entry — the generator only touches entries for ids present in the
  changelog event stream.

## What gets deleted from index.html once this exists

- `OFFMKT_727`, `RELIST_727`, `OFFMKT_727_NOTE`, and the body of
  `applyOffmkt727` → replaced by the `RECONCILE` marker block +
  `applyReconcile` (same two call sites, same semantics).
- The per-refresh hand edits to LIFE notes and SEED off-market prefixes stop
  accumulating; existing baked values stay as-is (history already shipped).
- CLAUDE.md's OFFMKT/RELIST bullets get rewritten to describe the marker
  region and the rule that only refresh.py writes inside it.

## Runbook — next cycle as it would look

```
1.  Export the two HAR CSVs (any variant with an Address column).
2.  python3 refresh/refresh.py --date 2026-08-10 single.csv split.csv
      → prints the diff summary (matched/dropped/new/relisted/excluded)
      → writes changes_2026-08-10.json + index.json
      → regenerates heights_solds.csv
      → splices the RECONCILE block in index.html
      → writes staging/proposed_2026-08-10.json (geocoded)
      → runs the verification battery; aborts before writing on any failure
3.  Review: staged pins (and any mergeCandidates); get Spencer's dispositions.
4.  python3 refresh/refresh.py set-disposition act_x sold …   (as rulings land)
5.  python3 refresh/apply_staged.py --approve …               (reviewed pins)
6.  git diff review → commit → auto-push → cache-busted curl verify.
```

Steps 3–5 are the human gate; everything else is generated. One refresh ends
as one commit with machine-consistent artifacts and a permanent history entry.
